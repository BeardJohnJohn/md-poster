# 为什么选 HTML + 截图，不用 Canvas

## 问题的本质

小红书图文排版的本质是：**把文字按照固定规则渲染成图片**。

这个任务有两种实现路径：

| 路径 | 代表工具 | 核心操作 | 本质 |
|------|---------|---------|------|
| 手动路径 | Canvas / PS / 美图秀秀 | 拖拽、对齐、调字号 | 人工渲染 |
| 代码路径 | HTML + CSS + Playwright | 写规则、跑脚本 | 机器渲染 |

两条路径的产出物完全一样——都是 PNG 图片。

区别在于**边际成本**：
- 手动路径：每多一页，成本不变（你还要再拖一次）
- 代码路径：第一次写模板有固定成本，之后**边际成本趋近于零**

## 为什么 AI 时代代码路径必胜

2024 年之前，代码路径有一个致命门槛：**你得会写代码**。

2024 年之后，这个门槛不存在了。AI 天生擅长写 HTML/CSS。你只需要用自然语言描述你想要的排版效果，AI 就能生成完整的模板。

| 能力 | AI 对拖拽工具 | AI 对代码工具 |
|------|-------------|-------------|
| 理解指令 | 无法操控 Canvas 的鼠标 | 直接输出 HTML/CSS |
| 保持一致 | 每次都要重新调 | CSS 锁死，永远一致 |
| 批量处理 | 做不到 | 循环脚本一行搞定 |
| 迭代修改 | 全部重做 | 改一行 CSS |

这就是为什么「HTML + 截图」不只是一个技巧，而是一种**思维范式的转换**：从「操作」到「定义规则」。

## 这套方案的局限

- **不适合**需要大量图片拼贴的视觉类内容（摄影、穿搭）
- **不适合**需要手绘/手写体效果的个人化风格
- **最适合**以文字为主体的深度内容、教程类、分析类文章
- 需要安装 Python + Playwright，有一定技术门槛（但 AI 可以帮你解决）
